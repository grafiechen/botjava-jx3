# JX3API WebSocket 推送事件清单

来源：`https://www.jx3api.com/openapi.socket.json`，连接地址按官方文档为 `wss://socket.nicemoe.cn`。

说明：

- `jx3api.ws.enabled=true` 时启动 JX3API 游戏事件 WebSocket，必须配置 `jx3api.ws.ws-url` 和 `jx3api.ws.ws-token`。
- 这组 WS 只用于游戏事件推送，和 QQ v2 WebSocket 消息入口不是同一个连接。
- 重连间隔使用 `jx3api.ws.re-connect-delay-seconds`（环境变量 `JX3API_WS_RECONNECT_DELAY_SECONDS`），默认和最小值均为 30 秒；重复断线/错误回调不会创建并发重连任务。
- 已有类型化 DTO 的事件继续按 `@WsActionData` 解析；未类型化事件由 `GenericWsData` 兜底接收。
- WS 事件正文同时兼容旧格式 `data` 与当前线上格式 `detail`；两者都缺失时记录 action 后忽略，不进入主动推送。
- `action=2004` 线上 `detail` 字段已验证为 `tags/zone/server/tieba/title/url/date`，其中 URL 不进入 QQ 推送正文。

## 群主动推送规则

- 每个事件自动注册为独立 `JX3API_WS` 推送任务，任务名取表格中的事件名；两条同名“关隘首领”分别显示为“关隘首领事件”和“关隘首领通知”。`推送列表` 表格会将这些任务与 QQ WS 群状态事件分来源展示。
- 群订阅默认关闭。群主或管理员先执行 `群设置 主动消息 开启`，再执行 `开启推送 任务名`；使用 `推送列表` 查看全部状态。
- WS 事件按规范化 JSON 的 SHA-256 指纹持久化去重，同一 `task_code + event_fingerprint` 只处理一次，应用重启和多实例部署不会重复推送。
- 去重记录默认保留 7 天；通过 `BOT_PUSH_WS_DEDUP_RETENTION_DAYS` 与 `BOT_PUSH_WS_DEDUP_CLEANUP_CRON` 调整。
- WS 收包线程不直接调用 QQ；事件进入 `groupPushExecutor` 有界线程池后逐群调用统一主动消息发送器。
- 已收到并按真实 JX3API WS `action=2004/detail` 帧完成解析验收；QQ 正式群主动推送仍需在目标群开启主动消息与“八卦速报”订阅后验收。仓库测试覆盖任务注册、默认关闭、群隔离、重复事件拦截、真实 2004 帧解析及推送正文。
